# ADR-0012: Swashbuckle is the single Swagger document generator

- **Status:** Accepted (2026-11-11). Supersedes ADR-0008 decision 1 and its Swagger UI wiring.
- **Date:** 2026-11-11
- **Affects:** `Program.cs`, `Extensions/SwaggerExtensions.cs`, `Swagger/`, `MediPassPlus.Api.csproj`, AGENTS.md,
  README, onboarding, every endpoint PR

## Context

ADR-0008 chose `Microsoft.AspNetCore.OpenApi` as the only document generator and `Swashbuckle.AspNetCore.SwaggerUI`
as a viewer. In practice the API also registered Swashbuckle's `SwaggerGen` (MP-1297), so two generators coexisted:
`/openapi/v1.json` was never mapped, and the document Swagger UI actually served was
`/swagger/v1/swagger.json`, generated by Swashbuckle.

That divergence caused a real failure. Two DTOs share the simple name `ClinicDto`
(`Application.Clinical` for public search and `Application.Dtos.AdminManagement` for admin screens). Swashbuckle
defaults the schema id to the bare type name, so generating the document threw a duplicate-schemaId exception and
`/swagger/v1/swagger.json` returned 500.

The team decision on 2026-11-11 is to keep the generator that is actually wired and delete the unused one, so the
repository has one document, one configuration surface and one set of schema rules.

## Decision

1. **Swashbuckle is the single generator and UI.** `Swashbuckle.AspNetCore` provides `SwaggerGen` and
   `SwaggerUI`. `Microsoft.AspNetCore.OpenApi`, `AddOpenApi`, its transformer and its package reference are removed.
2. **URLs.** UI: `/swagger`; document: `/swagger/v1/swagger.json` (document name `v1`). `/openapi/v1.json` is no
   longer mapped.
3. **Schema ids are namespace-qualified.** `Swagger/SwaggerSchemaId.cs` builds each id from the full namespace, the
   declaring-type chain for nested types and the generic arguments. Two types with the same simple name therefore get
   different ids, and an open generic and its closed forms stay distinct.
4. **The Bearer requirement is selective.** `Swagger/AuthorizeOperationFilter.cs` adds it only to operations whose
   endpoint metadata contains `[Authorize]`; anonymous endpoints stay unmarked. The scheme itself is registered once
   by `AddSwaggerDocumentation`.
5. **XML comments are included** with `IncludeXmlComments` from the `MediPassPlus.Api.xml` file generated by
   `<GenerateDocumentationFile>`.
6. **Exposure is unchanged.** The UI and the document are mapped only in Development or when
   `OpenApi:ExposeOutsideDevelopment` is `true`; the default stays `false`.

## Consequences

- One generator, one document and one place to configure security, XML comments and schema ids.
- Schema names in the document change from bare type names to namespace-qualified names, for example
  `ClinicDto` becomes `MediPassPlus_Application_Clinical_ClinicDto`. The previous document was broken, so there was no
  stable generated-client contract to preserve.
- `/openapi/v1.json` disappears. Any local bookmark, script or note that used it must point at
  `/swagger/v1/swagger.json`.
- The regression is covered by `SwaggerSchemaIdTests` (id uniqueness) and `SwaggerDocumentTests`
  (`GET /swagger/v1/swagger.json` returns 200 and contains both `ClinicDto` schemas).
- Moving back to the built-in generator later is a new ADR, not an incremental change.

## Alternatives considered

- **Keep `Microsoft.AspNetCore.OpenApi`, delete Swashbuckle `SwaggerGen`, point Swagger UI at `/openapi/v1.json`**
  (the ADR-0008 design). It would remove the working generator and require re-implementing the JWT and XML wiring on
  the other stack. Rejected by the 2026-11-11 decision: the team uses the Swashbuckle document and its UI integration.
- **Keep both generators.** Rejected: two contracts drift, the duplicate-schemaId failure proved it, and no requirement
  needs two documents.
- **Rename one `ClinicDto` instead of changing schema ids.** Rejected: it hides the problem for this pair only; the
  next same-named DTO would break the document again.

## Conflict check

No conflict with the requirements. NFR-MNT-03 requires endpoints to be documented in Swagger/OpenAPI; Swashbuckle
produces an OpenAPI 3 document. ADR-0008 remains in the history as superseded.
